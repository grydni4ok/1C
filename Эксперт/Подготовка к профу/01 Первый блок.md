## Настройка оборудования Perfomance monitor

Параметры для натсройки ОС Windows:
  1. Memory (Память) - Commited bytes in use (% использования выделенной памяти) - счетчик показывает процент относительно суммы размера оперативной памяти и файла подкачки, а не только использование оперативной памяти. Не должен превышать рамера оперативной памяти
  2. Memory (Память) - Available Mbytes (Доступно, Мбайт) - счетчик позывает объем свободной физической оперативной памяти. Приближение к нулю свидельствует о недостатек оператвной памяти.
  3. Processor [_Total] (Процессор [_Total]) - % Processor Time (% загрузки процессора) - рекомендованный максиму не более 70% в течении длительного времени.
  4. System (Система) - Processor Queue Length (Очередь к процессорам) - рекомендованный максимум - не боле 2* на количество ядер процессоров в течении длительного времени.
  5. Phisical Disk (Физический диск) - Avg. Disk Queue Length (Средяня длина очереди к дискам) - обязательно для системных дисков отдельно, для диска с базой отдельно, для диска с жерналом транзакций (если такой есть) отдельно. Рекомендованный максимум не более 2 * количество дисков, работающих параллельно.
  6. Logical Disk - % Free Space - показатель наличия свободного места на диске и динамики его изменения.
  7. Network Interface (Сетевой интерфейс) - Bytes Total/sec (всего байт/с). Рекомендованный максимум не более 65% от пропускной способности адаптера в течении длительного времени.

Настройка для СУБД MS SQL Server:
  1. SQLServer:Buffer Manager | Page life expectancy (PLE) - Показывает, сколько секунд страница данных находится в буферном кэше (оперативной памяти) без обращений. **Высокое PLE (хорошо)**: Страницы живут в памяти долго (например, > 300-600 секунд). Данные переиспользуются, повторных чтений с диска мало. Низкое PLE (плохо): Значение падает (например, < 100-200 секунд или постоянно "проседает" до минимума). Это означает, что страницы вытесняются из памяти очень быстро, чтобы освободить место для новых. Это прямой признак дефицита памяти (memory pressure) для SQL Server

Как найти, из какой именно директории запущен кластер серверов?
  1. **Запустить ragent из консоли с указанием портов. В случае запущенного кластера на тех же портах будет выдана ошибка с указанием пути, откуда ранее был запущен кластер** 
  2. Запустить ragent как сервис е с указанием портов. В случае запущенного кластера 
на тех же портах будет выдана ошибка с указанием пути, откуда ранее был запущен 
кластер
  3. В технологическом журнале всегда написано, из какой именно директории запущен кластер серверов
  4. С помощью диспетчера задач

Пояснение:
Речь идет о серверах 1С:Предприятия (кластер серверов). В ОС Windows кластер 1С работает как служба (ragent.exe — агент сервера). Чтобы узнать, из какой директории запущен работающий кластер, можно воспользоваться следующим методом:
  1. (рабочий): Попытаться запустить ragent.exe из консоли (командной строки) с теми же сетевыми портами, которые использует работающий кластер (по умолчанию 1540 для агента и 1541 для менеджера кластера, либо порт 1545 для сервера лицензирования). Так как порты уже заняты работающим экземпляром, новый экземпляр не сможет их занять и выдаст сообщение об ошибке. В этом сообщении будет указано, какая программа (ragent.exe) уже использует эти порты, и, соответственно, полный путь к этой программе (откуда запущен кластер).
  2. (некорректный): Запуск ragent как сервиса не даст такого же эффекта, так как сервис не будет интерактивно выводить сообщение в консоль. Управление сервисами (services.msc) может показать путь к исполняемому файлу службы, но это путь к файлу, прописанный в реестре при установке, а не обязательно "директория запуска" в данный момент (хотя в большинстве случаев это одно и то же). Однако предложенный в вопросе синтаксис с запуском как сервиса (ragent как сервис е) не является стандартной командой для получения пути.
  3. В технологическом журнале (ТЖ) действительно указывается информация о кластере, но для его включения нужна настройка, и он не всегда ведется на рабочем сервере. Рассчитывать только на него для решения этой задачи ненадежно.
  4. Диспетчер задач (Task Manager) может показать запущенный процесс ragent.exe, но в обычном режиме он не показывает полный путь к исполняемому файлу (только имя процесса). В современных версиях Windows (10/11/Server 2016+) можно добавить столбец "Командная строка" (Command line), который покажет путь, но это не самый надежный и очевидный метод, описанный в варианте ответа.
